# PHASE 3 — Art Direction Breakthrough

本轮保留当前手机首页，只在独立评审入口实现三套可比较的 Game Pass。没有自动选定正式方向，`/` 继续使用已通过的 Phase 2 票面。

评审入口：`/review/art-direction`。A / B / C 切换仅属于开发评审；`capture=1` 隐藏评审工具栏，截图来自正常的 `CalendarApp`，保留品牌、球队及城市交互、未来赛程和底部导航。

## 三种构图

| 方向 | 图形核心 | 票根结构 | 当地时间表达 |
| --- | --- | --- | --- |
| A · Editorial Sports Ticket | 超大 HOU 与错位的 LAL 承担构图；一条被中圈打断的 Match Line 形成篮球场几何 | 下方横向可拆副券，编号与比赛序号横向并置 | 安静的 24 小时线性刻度，独立时标随实际当地时间移动 |
| B · Precision Time Instrument | 球队位于顶端，270° 的 24 小时刻度把城市与比赛时间组成仪器 | 窄幅右侧副券、纵向个人编号，主券下缘保留赛季刻度 | 00:00–24:00 映射固定的 270° 弧段；Tokyo 与 London 的光标、小时段、城市和 GMT 一起更新 |
| C · Modern Collectible Stub | 不对称 HOU / LAL、中心线与中圈、局部球队色印刷边条 | 较宽的机械副券、纵向六位个人编号、上下撕口与保留 Bridge | 独立的城市 / 时间块，加下方 24 小时标尺 |

三套构图共享 `PersonalPass`，没有并行的宣传假数据。当前测试样例为 HOU—LAL、25 OCT 2026、GAME 01 / 82、SEASON 26–27、PASS 0147、MG+ Nº 047295、TOYOTA CENTER。

`047295` 是现有个人赛事 serial 的六位印刷格式。更换城市不重新签发编号；本轮没有增加全球唯一编号后端。

## 两座城市的数学含义

Tokyo 是 `10:00 / GMT+9`；London 是 `01:00 / GMT`。日期、球队、比赛序号、用户及个人编号不变。这个比赛时刻恰逢英国夏令时结束，因此 London 采用真实 IANA 换算后的 GMT。

A / C 线性标尺直接表示 00:00–24:00 的当地钟面分钟数。B 采用同一数值映射到 270° 弧段。这些图形没有地理距离含义；同一时区的不同城市可以拥有不同城市身份，同时共享正确的当地时标。

82 个 marks 都是独立的赛季比赛位置，当前比赛只高亮自身位置。刻度位于票的下边缘，不作为完成进度条或滚动条。

## 评审方式与边界

`design/promo/export-art-directions.cjs` 从运行中的生产 App 导出六张同框手机截图、独立票面裁切、两种联系表与诊断图。所有手机截图固定 600×800 CSS viewport、DPR 1.8，对应 1080×1440 PNG。

自动检查负责确认：

- 六张图的真实数据、编号、比赛和赛季相同，城市切换只更新 Location。
- 三种方向占据相同的票面位置与尺寸，页面外围几何及像素保持一致。
- 默认首页与已提交的 Phase 2 东京截图逐像素一致。
- 所有 PNG 均完整解码、尺寸正确且非空。
- 每张票恰有 82 个独立赛季 mark、一个当前序号，以及会真实移动的当地时间 marker。
- 320 / 390 / 480 CSS px 下没有横向溢出；标准手机截图中赛程与底部控制器不重叠。
- 非截图模式下 A → B → C 切换保留已选 London、HOU—LAL 与同一编号；每个方向均可切换 LAL / GSW，再恢复 HOU。整个交互过程对 `mygame_pass_id` 的新增写入次数为 0。
- 没有应用或 hydration 错误。浏览器对缺省 `/favicon.ico` 的自动请求单独记录，不当作票面资源。

视觉评审使用以下诊断图，判断与自动检查分开：

1. **Silhouette**：模糊后比较 A 的错位大字与横副券、B 的时间弧段、C 的色边与宽副券。构图不同不依赖字号差几像素。
2. **Sports**：隐藏球队缩写与 NBA 标签后，检查中圈 / 中线几何是否仍有篮球场来源。B 的时间仪器本身表达功能，体育身份由其 Match Mark 补足。
3. **Ticket**：隐藏 GAME PASS 标签，检查撕口、微冲切、主副券比例和机械编号是否仍然构成凭证。
4. **Collectible**：六位 personal issue 应成为第二、第三眼可发现的身份信息。是否产生“我的编号是多少”的欲望，需要真实用户反馈。
5. **Timezone**：Tokyo / London 除数字外，时标位置、城市及 GMT 必须发生真实变化。
6. **Screenshot**：独立票面裁切保留比赛、当地城市、时间和个人编号，不依赖外围 App 才能理解。
7. **Brand**：隐藏 MG+ 标记后，检查 Match Line、时间刻度、赛季下缘与票根构造的组合是否仍有识别潜力。

视觉诊断可证明构图差异、可读性与系统行为；不能替代保存意愿或品牌认知的用户研究。本轮不替用户选择 A / B / C，也不新增功能作为视觉问题的补偿。

最终测量与文件清单见 `output/art-direction/validation.json`。

## 本次实测结果

75 项单元测试、生产构建、已有 9 组 App 浏览器检查及 3 组身份签发检查通过。新增评审导出检查通过，六张手机 PNG 都可完整解码为 1080×1440，六张独立票面裁切均为 1080×856。

所有方向、两座城市的票面边界相同：`x 88 / y 225.15625 / width 424 / height 335.46875` CSS px。四组 A/B、A/C 同城市比较，票面范围之外的像素差均为 **0**。默认首页与已提交的 Phase 2 东京成品逐像素差为 **0**。

已查看最终联系表、手机缩略图、三种模糊图、隐藏球队与 NBA 的图、隐藏 GAME PASS 的图，以及隐藏品牌标记的图。观察记录如下；这些是设计审阅，不伪装成用户研究结论。
